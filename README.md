# Hold Tight! (꽉 잡아!)

2인 온라인 협동 코미디 물리게임 MVP.
물리/네트워크 검증 위에 게임 루프와 **타이틀 / 방 시스템**을 얹은 상태.

## 게임 규칙

- **목표**: 노란 아웃라인이 켜진 **냉장고**(소품 id 3, 20kg)를 초록 원으로 표시된
  **출구**(+X 벽 앞, 좌표 `x 13.4 / z -1.0`, 반경 1.6m)까지 옮긴다.
- **제한시간**: 3분. 화면 상단 중앙에 남은 시간이 뜨고, 30초 이하면 빨갛게 깜빡인다.
- **성공**: 냉장고가 출구 원 안에 0.25초 이상 머무르면 «성공!»
  (한 프레임 스쳐 지나가는 오판정과, 벽 너머로 던져 넘기는 꼼수는 막아 뒀다 — 높이 3m 상한)
- **실패**: 시간 초과 시 «실패!»
- **다시하기**: 결과 화면의 버튼. 소품 26개 전부와 캐릭터를 스폰 위치로 되돌리고 타이머를 리셋한다.

혼자서는 20kg을 들 수 없어 **바닥에 둔 채 밀어야** 하고, 둘이 같이 잡으면
**번쩍 들어서** 옮길 수 있다 (`carry.ts`의 들기/밀기 예산 분리 참고).

## 맵 (3개)

| # | 맵 | 목표 | 제한시간 | 특징 |
|---|---|---|---|---|
| 1 | 집 | 냉장고 | 3:00 | 거실을 가로질러 현관으로. 가구가 많다 |
| 2 | 창고 | 공구함 | 2:45 | 선반 열과 팔레트 더미가 통로를 꺾는다. 대각선 약 33m |
| 3 | 옥상 | 실외기 | 2:30 | 벽 대신 난간이라 떨어뜨리기 쉽다. 실외기·환기구가 경로를 막는다 |

성공하면 결과 화면에 **[다음 맵 →]** 이 뜨고, 마지막 맵을 깨면 «전체 클리어!» 와
**[처음부터]** 가 뜬다. [다시하기]는 언제나 그대로다.

맵 정의는 `maps.ts`의 `MAPS` 배열 하나에 모여 있다 — 목표 소품 id, 출구 좌표,
스폰 지점, 제한시간, 바닥/배경 색, 그리고 지형을 짓는 `build()`. 맵을 추가하려면
이 배열에 항목 하나를 더하면 된다.

### 맵 전환에서 조심할 것

- **정적 바디를 추적해야 한다.** `mapkit.ts`의 `staticBody()`가 만드는 벽·가구
  바디를 `Build.bodies`에 모아 두고, 맵을 내릴 때 전부 `removeBody` 한다.
  안 빼면 보이지 않는 예전 맵의 벽에 캐릭터가 부딪힌다.
- **지오메트리/머티리얼은 dispose 하지 않는다.** `boxGeo/cylGeo/sphGeo/toyMat`은
  전부 캐시를 거치고 맵끼리 공유한다. 여기서 해제하면 다음 맵이 이미 풀린 GPU
  버퍼를 참조한다. 씬 그래프와 물리 월드에서 빼는 것으로 충분하다.
  (반대로 `game.ts`의 출구 마커는 캐시를 안 쓰므로 반드시 dispose 한다)
- **`objects`/`objectById`는 새로 만들지 않는다.** main.ts가 참조를 붙들고 있어서
  배열을 갈아치우면 옛 맵을 가리킨 채 남는다. 제자리에서 비우고 다시 채운다.

실측: 집 → 창고 → 옥상 → 집 을 3회 왕복한 뒤 물리 바디 236개 / 씬 자식 38개 /
소품 26개로 초기값과 정확히 일치 (누수 없음).

## 캐릭터 선택

타이틀에서 [싱글 플레이] / [멀티 플레이] 를 고르면 **캐릭터 선택 화면**을 거친다.
프리셋 8개(`characters.ts`)를 CSS로 그린 미리보기와 함께 보여주고, [확인]을 누르면
싱글은 바로 시작 / 멀티는 방 화면으로 간다. 대기실의 [캐릭터 변경]으로 다시 고를
수도 있다.

- **겹침 방지**: 선택은 서버가 방 단위로 들고 있다(`picks`). 이미 남이 고른
  프리셋을 보내면 서버가 거절하고 현재 현황을 되돌려주며, 클라이언트는 비어 있는
  첫 캐릭터로 자동으로 옮겨간다. 대기실에서는 남이 쓰는 캐릭터가 흐리게 표시된다.
- 선택을 **서버가 모으는 이유**는 「서로조종」 때문이다. 각자 로컬에서 정하면 내
  화면의 파란 옷이 상대 화면에서는 빨간 옷이 되어 누구를 조종 중인지 헷갈린다.
- 아직 아무것도 안 고른 사람은 id 기반 기본값으로 떨어진다(팔레트 길이와 서로소인
  보폭이라 id가 연속이면 반드시 다른 캐릭터가 나온다).

## 타이틀 / 방 시스템

접속하면 먼저 타이틀 화면이 뜬다. 뒤에서는 방이 실제로 렌더링되면서 카메라가 천천히 돈다.

```
Hold Tight!  (꽉 잡아!)
   ├─ [싱글 플레이]  → 서버에 연결하지 않고 즉시 시작 (로컬 단독, 자기 캐릭터 조종)
   └─ [멀티 플레이]
        ├─ [방 만들기]    → 서버가 4자리 코드를 만들어 준다 → 대기실
        └─ [방 참가하기]  → 코드 입력 + [입장]           → 대기실

대기실: 방 코드(눌러서 복사) · 접속 인원 목록 · 방장만 [게임 시작]
        → 누르면 방 전원이 동시에 게임 화면으로 넘어간다
```

- 코드는 `ABCDEFGHJKLMNPQRSTUVWXYZ23456789` 32글자에서 뽑는다.
  전화로 불러줄 때 헷갈리는 `0/O`, `1/I`는 빼 뒀다. 입력은 대소문자를 가리지 않는다.
- 방 하나에 최대 4명 (`main.ts`의 스폰 지점 개수와 맞춰 뒀다).
- 릴레이는 **전부 방 안에서만** 일어난다. 다른 코드를 쓰는 사람끼리는 입력도
  스냅샷도 서로 보이지 않는다 (`npm run test:room`이 이걸 검증한다).
- 마지막 사람이 나가면 방은 지워지고 코드는 다시 쓸 수 있게 된다.

## 실행

터미널 2개 필요.

```bash
npm install

# 터미널 1 — WebSocket 서버 (포트 8080)
npm run server

# 터미널 2 — 클라이언트 (포트 5173)
npm run dev
```

브라우저에서 `http://localhost:5173` 접속.
멀티로 놀려면 탭 하나에서 [방 만들기] → 나온 코드를 다른 탭에서 [방 참가하기]에 입력.

싱글 플레이만 할 거면 `npm run server`는 띄우지 않아도 된다.

## 다른 컴퓨터에서 접속

같은 와이파이에서 PC의 로컬 IP 확인 후(`ipconfig`), 다른 기기에서:

```
http://<PC_IP>:5173
```

클라이언트는 접속한 호스트명 기준으로 `ws://<hostname>:8080`에 연결하므로 별도 설정 불필요.
윈도우 방화벽에서 5173, 8080 인바운드 허용 필요할 수 있음.

### game.ts가 물리를 건드리지 않는 방식

게임 규칙은 물리·캐릭터 코드와 완전히 분리돼 있다.

- `game.ts`는 씬에 **장식 메시만** 붙인다 (바닥 원, 빛기둥, 문틀, 아웃라인, 화살표).
  물리 바디는 하나도 만들지 않으므로 캐릭터가 출구 표시에 걸려 넘어지지 않는다.
- 판정은 `objectById.get(3).body.position`을 **읽기만** 한다.
- 월드를 되돌리는 일만 `main.ts`가 훅(`resetWorld`)으로 제공한다 —
  래그돌과 grab 제약은 `main.ts`가 소유하고 있어서 밖에서 만지면 위험하기 때문이다.
  (제약을 남긴 채 바디를 텔레포트하면 그 프레임에 물리가 폭발한다)

## 네트워크 모델

- 릴레이는 **방 단위**다. 서버는 소켓마다 소속 방을 기억하고, 그 방 밖으로는
  입력도 스냅샷도 내보내지 않는다.
- 방의 첫 접속자가 **host**. 오브젝트 물리는 host만 계산한다.
- 각 플레이어는 자기 캐릭터를 로컬에서 물리 계산하고 20Hz로 상태 전송.
- 다른 플레이어는 kinematic body로 복제 → 충돌은 되지만 상대 물리에 끌려가지 않음.
- 비-host의 grab 요청은 서버가 host에게 전달 → host가 constraint 생성.
- host가 오브젝트 위치/회전을 20Hz로 broadcast → 나머지는 lerp/slerp 보간.
- host가 나가면 서버가 남은 플레이어에게 host를 넘긴다.
- **게임 상태**(진행중/성공/실패 + 남은 시간)도 host가 계산해서 snapshot에 얹어 보낸다.
  비-host는 표시만 한다. host가 바뀌면 마지막으로 받은 시간에서 이어서 센다.
- **[다시하기]** 는 월드 리셋이므로 host만 실행할 수 있다.
  비-host가 누르면 `restart` 메시지가 서버를 거쳐 host에게 전달된다.
- **대기실**: 방장이 `startGame`을 보내면 서버가 그 방 전원에게 `gameStart`를 뿌린다.
  클라이언트는 이걸 받기 전까지 래그돌을 스폰하지 않는다.
  이미 시작된 방에 늦게 들어오면 접속 즉시 `gameStart`를 받아 바로 합류한다.

### 잡기 모션 (grab reach)

E로 잡으면 손이 실제로 물체 표면까지 뻗는다. 예전에는 손이 몸 옆에 늘어진 채
물체만 밀려가서 "허공에서 원격으로 잡은" 그림이었다. 세 가지가 겹쳐 있었다.

1. **무거운 물체엔 제약이 아예 없다.** 냉장고는 밀기 모드(강체 제약 없음)라
   손을 표면으로 끌어줄 게 하나도 없었다. → 잡은 지점을 향한 **힘 기반**
   손 스프링을 건다. 솔버 제약이 아니라 힘이라서 "물체-손-팔-몸통-지면" 닫힌
   고리로 인한 교착이 생기지 않는다.
2. **팔에 목표 자세가 없었다.** 캐리 포즈는 "몸통 앞 고정 방향"이었고 그마저도
   못 드는 물체엔 안 썼다. → 어깨/팔꿈치를 **실제로 붙잡은 지점** 쪽으로 겨눈다.
   팔 무게(어깨 기준 중력 토크 약 7 N·m)를 feed-forward로 상쇄해서, 위팔이
   폭발하지 않는 범위의 토크(6.5 N·m)로도 팔이 펴진다. 반작용은 몸통에 되돌린다.
3. **감쇠를 월드 속도로 걸고 있었다.** 서 있을 땐 손이 붙는데 걷기 시작하면
   0.25m씩 떨어졌다. 3 m/s로 같이 움직이는 중에도 `-Kd * v`가 뒤로 37N을
   걸어서 앞으로 당기는 30N을 상쇄했기 때문이다. → **잡은 지점 대비 상대속도**로
   감쇠한다.

여기에 밀기 모드에서는 붙잡은 점을 매 프레임 표면에 다시 투영하고(팔이 닿는
자리로 미끄러진다), 물체가 팔 길이 밖으로 뒤처지면 `pushCatchGain`으로 따라오게
한다. 실측 손↔표면 거리(손 반지름 0.085 = 딱 닿은 상태):

| 상황 | 고치기 전 | 고친 후 |
|---|---|---|
| 냉장고 잡고 정지 | 0.58 | 0.085 |
| 냉장고 앞으로 밀기 | 0.24 | 0.084 |
| 냉장고 뒤로 끌기 | 0.69 | 0.085 |
| 가벼운 상자 (제약 O) | — | 0.006~0.02 |

### 캐릭터 외형 (2.8등신 SD 비율)

`VIS` 배수로 **렌더 메시만** 바꾼다. 충돌체(`DIM`)는 건드리지 않는다 -
rideHeight(0.86)·관절 pivot·총질량·관성모멘트가 전부 거기서 나오고 그 위에
서기/걷기 게인이 실측으로 맞춰져 있다. 특히 **다리 길이를 줄이면 골반이
rideHeight에 있을 때 발이 바닥에 안 닿아 캐릭터가 공중에 뜬다.**

`VIS`는 파츠마다 `{ r: 굵기배수, len: 캡슐길이배수, up?: 위로올림 }` 이다.

- **길이를 줄여도 관절 사이가 안 벌어지는 이유**: 캡슐이 축방향으로 덮는 길이는
  `sep + 2r` 이다. len으로 sep을 줄여도 r을 그 이상 키우면 총길이가 물리 캡슐보다
  길어져 오히려 더 겹친다. (위팔: 물리 0.35 → 렌더 0.448)
- **굵기에는 기하학적 상한이 있다.** 처음에 몸통 1.45 / 골반 1.80 / 팔다리 2.0으로
  잡았더니 갈색 기둥 하나로 뭉쳐서 팔다리가 아예 안 보였다.
  다리는 hipX = ±0.14에 있어 반지름이 0.14를 넘으면 두 다리가 합쳐지고,
  몸통이 굵어질수록 어깨(±0.29)의 팔이 파묻힌다. 골반이 몸통보다 굵으면 기저귀다.
- **머리는 0.16m 올린다.** 물리 머리 중심이 어깨보다 0.31m밖에 안 위라 반지름
  0.37짜리 머리를 그대로 두면 어깨와 상의를 통째로 덮는다(실측: 셔츠가 0.27m
  띠로만 보였다). 지오메트리에 오프셋을 구워넣어 물리는 그대로 둔 채 올린다.

물리 영향 실측 — 30초 정지 시 pelvisY 진폭 **0.000**, R키 넘어짐→복귀 3/3 성공,
WASD 방향 정상, E 잡기 손 간격 0.084 (= 손 반지름, 딱 닿은 상태). 비율 변경 전과
동일하다.

옷은 `playerId`로 정한다. 랜덤이면 내 화면의 파란 옷이 상대 화면에서 빨간 옷이
되어 「서로조종」에서 누구를 조종 중인지 헷갈린다. 상의/하의/신발은 팔레트 길이와
**서로소인 보폭**으로 건너뛰며 골라서, id가 연속인 사람끼리는 반드시 다른 색이
나온다 (해시로만 뽑았더니 12명 중 6명이 같은 파란 상의를 입었다).

### 물리 엔진에서 조심할 것 (실측으로 데인 부분)

`world.ts`에 자세히 적어 뒀지만 요약하면:

- **`SAPBroadphase`를 쓰면 안 된다.** 정렬 키(`aabb.lowerBound`)와 스윕 종료 판정
  (`position ± boundingRadius`)이 서로 안 맞고, 정적 바디의 AABB는 갱신되지 않아
  원점에 굳어 있다(실측: 236개 중 194개). 그래서 스윕이 엉뚱한 데서 끊기고
  **캐릭터가 소품을 그대로 통과했다.** `NaiveBroadphase`를 쓴다.
- **마찰 상한은 "힘"이 아니라 "한 스텝 충격량"이다.** cannon-es는 접촉점마다
  `maxForce = μ·|g|·reducedMass` 를 넣고 GSSolver가 그 값을 lambda(충격량)에 clamp한다.
  즉 실효 마찰력 상한은 그것을 `dt`로 나눈 값 — μ=0.2/20kg/60Hz면 접촉점당 4320N이다.
  원하는 실효 계수가 있으면 **`μ = μ_eff × dt`** 로 넣어야 한다.

## 방 시스템에서 자동 검증된 것

`npm run test:room` (28개):

- [방 만들기]가 4자리 코드를 돌려주고, 만든 사람이 방장이 된다 / 방마다 코드가 다르다
- 같은 코드로 들어가면 서로를 명단에서 본다 (소문자로 입력해도 같은 방)
- **다른 코드끼리는 입력도 스냅샷도 섞이지 않는다**
- [게임 시작]은 방장만 할 수 있고, 그 방에만 퍼진다
- 이미 시작된 방에 늦게 들어오면 곧바로 합류한다
- 없는 방 / 형식이 틀린 코드는 `joinError`로 거절된다
- 방장이 나가면 이양되고, 마지막 사람이 나가면 방이 지워진다
